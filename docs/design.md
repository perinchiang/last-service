# First playable

An industrial facility that has outlived its human staff. A service robot first scans the scene, infers that its supervisor is missing, and forms the goal of locating them. The gate refuses to open without human authorization. The robot's MK.04 is a maintenance pulse tool: maintenance output is available, but security-target fire is locked until the robot’s local safety controller detects an imminent threat and grants a temporary self-defense exception.

The current prototype stays inside one maintenance hall: exploration alternates with combat, and the player can alter the fight by releasing suspended cargo. Desktop browser first, with basic touch controls for phone playtesting. One skippable in-engine boot diagnosis, one maintenance pulse tool, hovering security drones, and a manual gate release. The boot HUD presents scripted perception → tool call → result → inference → goal updates. It does not expose per-frame engine functions. Routine action summaries are rate-limited to roughly one per 30 seconds; critical story and combat events appear immediately. No obligatory mirror puzzle. Reflective material is an optional part of lighting, not a game mechanic.

Stage checkpoints: (1) reproducible project and repository; (2) procedural room, boot diagnosis and cinematic; (3) full combat, sound, touch input and restart; (4) human playtest of the one-room battle, especially whether players notice and use the cargo hazard; (5) expand into a few functional rooms only if the combat decisions validate; (6) browser verification and release.

The proposed human-shaped robot remains deliberately simple and mostly off-camera. First-person hands, the tool, reloading and physical interaction carry its character; a detailed skinned humanoid and complex full-body locomotion rig are not required for the current scope.
